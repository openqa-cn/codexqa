# 已知边界与失败情形

[English](KNOWN_LIMITATIONS.md)

这里每条都是代码里能看到的，或跑过之后观察到的，不是免责声明。评估这个包时，本页比功能列表更有用。设计背景先读[工作原理](HOW_IT_WORKS.zh-CN.md)。

## 默认后端是 mock，「构造成功」可能几乎没有含义

开箱时 executor 指向 `DATA_BUILD_API_BASE`，默认 `http://127.0.0.1:8765`——自带的 `slots/mock_server.ts`。mock 会发回 `p_1`、`o_1`、`d_1`，并追加到 `testdata/mock-store.json`。这够用来走通路由、场景顺序和回写，**不能**证明任何东西进了真实系统。

skill 不会区分 mock ID 和生产 ID，对着 mock 写出的 `case-executable.md` 和预发网关写出来的长得一样。信任回写之前，先确认是哪条 base URL 产的。

## 被测源码不是输入

没有 clone/diff，也没有 `code/` 目录。不会去读被测仓库来还原接口、表名或 ID。如果手里只有源码，没有用例包 / OpenAPI / `planId` / `serviceId`，本 skill 没有可构造的材料——这是缺料就停，不是暗示「从代码编一套 API」。

## 没有 API 来源时会停，而不是即兴发挥

第 4 步只根据已发现的 API 写构造脚本。工作区既没有 OpenAPI 目录，也没有 `planId`、`serviceId` 时，设计就是停下来问，而不是猜 endpoint。编造的接口会在很晚才失败，却看起来很权威。要走完全自动路径，补上三者之一，或在 `slots/` 下丢一个 slot。

业务标识也一样：用户给过的核心 ID 原样复用、绝不改写；缺的会问。可选字段走 executor 默认值，所以一次构造成功时，可能带上你没选过的值。

## 跨域场景不能自己造上游物料

distribution 的 `ready-to-sell` 需要只有 catalog 才能产出的 `productId`。场景不会自己跨域；上下文里没有 ID 就会问。多域流程因此需要已有 ID，或先跑一遍 catalog。被材料打断的场景要接着跑完，不要从头再来，否则前面的步骤会跑两遍。

## 第 1、2 步受检索质量限制

skill 搜索和工具注册表是对着 description 做语义查找。两个已知后果：

- 关键词必须是一两个业务名词。像「帮我构造」这种动词短语会差到脚本退回全量扫描。
- 收藏夹无条件返回，相关性由模型判断，脚本不做过滤。过期的 pin 会一直排在候选最前，直到 `favorites.ts rm`。

已验证方法还有第三种失败：语义对，但已经跑不了——绑定的工具挪了，或当前上下文缺必填参数。三条件适用性检查就是为此；跳过一行 proven 是正常的，不是报错。

## 用例流水线需要宿主尊重退出码

`pipeline.ts` 是可恢复的状态机，不是一条命令。退出 10 / 11 / 12 表示要启动对应 Agent，20 表示强制人工决策，并期望宿主合并补丁后 `--resume`。把非零退出当成失败的宿主会在中途放弃，磁盘上留下半份 `manifest.json`。lint 门最多三轮再交给用户，所以持续低置信的用例会停在提问，而不是一份干净产物。

## 企业适配器是契约，不是已验证的对接

每个平台关注点——skill 市场、工具注册表、API 目录、经验库、鉴权、SQL、配置、实验、文档源、用例回写、工作区上下文——都是带本地默认的适配器。示例和校验脚本练的是本地实现。HTTP 实现遵循 [references/adapters.md](references/adapters.md) 的契约，但包不带凭证，也无法验证某一家网关。把新的 `type: http` 适配器当成未验证，直到你用它完整跑通一次构造。

功能开关默认 `noop`。未配置时，skill 拒绝写开关，而不是退回裸 HTTP。

## Demo 默认值会过时

自带 catalog executor 带有演示默认（`city=demo-city`、`quantity=1`、`credits=1000`，履约日相对今天）。它们只为了 mock 流程只需一个必填字段，不是真实业务值。要紧的字段请显式覆盖。
