# Structure Inventory

Mark chapter presence before the source audit. Each cell is `present` / `thin` / `absent`. `absent` only means “no chapter”; it does not replace the NFR, success-metrics, or dependency grids.

| Marker | `present` | `thin` | `absent` |
| --- | --- | --- | --- |
| Background / problem | States the problem to solve | Slogan only | Missing |
| Goal / purpose | Can be mapped to later features | Vision sentence only | Missing |
| User stories / use cases | Role and intent exist | Titles only | Missing |
| Functional requirements | Observable behavior | Feature names only | Missing |
| Non-functionals | Dedicated section or explicit constraint | “Be safe / be fast” only | Missing |
| Boundary / exclusions | Says what is out or later | Vague “as needed” | Missing |
| Acceptance criteria | Observable failure condition | “Good experience” only | Missing |
| Success metrics / KPI | Section or numeric target | “Look at the data” only | Missing |
| Dependencies | Names systems or teams | “Needs coordination” only | Missing |
| Timeline / milestone | Date or milestone | “Soon” only | Missing |
| Design / prototype | Link or attached mock | “See design” with no link | Missing |

If the body is under about 200 words: still write the inventory, but mark later grids as “insufficient material, these are gaps” instead of pretending completeness.
