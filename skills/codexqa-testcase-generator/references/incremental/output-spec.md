# Incremental output contract

## Diff analysis

`artifacts/change-analysis/change-analysis.json` is generated by the Agent and at least contains `analysisContractVersion`, `changes[]`, and `limitations`. Each change contains `changeId`, `title`, `oldBehavior`, `newBehavior`, `impactDimensions`, `platformScope`, `evidenceRefs`, `confidence`, `rationale`, and `openQuestions`.

`confidence` is the Agent's judgment of the real change; do not reuse the script's `candidateConfidence`. When rendering to Chapter 4 of the user report, it must display as `Original logic` and `New logic`.

## Case decisions

One file per `platform + sourceId`: `artifacts/case-decisions/{platform}/{sourceId}/case-decisions.json`.

Every baseline case must be handled by one non-`ADD` action. Actions: `KEEP`, `MODIFY`, `ADD`, `SPLIT`, `MERGE`, `NEED_CONFIRM`, `DEPRECATE_CANDIDATE`.

Minimum fields: `decisionContractVersion`, `platform`, `sourceId`, `decisions[]`. Each decision contains `baselineCaseId`, `action`, `changeIds`, `evidenceRefs`, `rationale`; modification-class actions also need `changedFields`, `standardRefs`, and `afterCase`.

`KEEP` does not generate a rewritten copy; `MODIFY` changes only necessary fields; `ADD`, `SPLIT`, and `MERGE` must provide complete target content. `standardRefs` must point to both the corresponding end's `standard-profile.json` and the Chapter 3 snapshot.

## End-level delivery

```text
outputs/cases/{platform}/{sourceId}/
├── artifact.json
├── delivery-manifest.json
└── content/
    └── files or directories consistent with the source baseline
```

`delivery-manifest.json` at least contains:

- `platform`, `sourceId`, `formatProfileRef`, `caseDecisionsRef`, `contentRoot`, `entryFiles`
- `caseCount`: the number of real, parseable, and unique cases in the final delivery content. Count APP / Web by the result that is consistent between index and details; count Server by real case entries.
- `actionSummary`: the non-zero action distribution of the final output cases.
- `selfCheck`: the aggregated placement-validation conclusion for new target cases. When the check passes normally, do not save temporary anchors again per case.

## User report

Fixed path: `outputs/reports/review-summary.md`. Chapter order, fields, and the Chapters 5–8 layout must follow [report-spec.md](report-spec.md).

Publication results must also explicitly record:

- `testcaseRoot`: `{run_dir}/testcase/`
- End-level layout: APP / Web are index + `testcases/`; Server is a single file
- `publicationMode`, `baselinePath`, `caseBaselineSource`
- Actual operations, read-back status, and hashes of `casesTargetPath` and `procaseTargetPath`
- Update results of that end's basic-statistics `Total case count` and `Enhanced cases` rows
- `delivery-manifest.caseCount`, the report's updated case count, and the `Total case count` in the final files must be consistent
