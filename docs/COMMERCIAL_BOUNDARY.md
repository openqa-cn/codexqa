# Open source and commercial boundary

## Open source

- Skills and workflows
- Evidence schema
- CLI and CI integration
- Example projects
- Reproducible benchmark fixtures

## Commercial extensions

- Private repository and team history
- Enterprise test-asset graph
- Cross-repository change impact analysis
- Request-level coverage analytics
- Hosted execution, devices, and environments
- Enterprise identity, policy, audit, and private deployment

The open-source edition must be independently useful. Commercial products reduce organizational operating cost and preserve long-term context; they should not merely remove the first successful local workflow.
