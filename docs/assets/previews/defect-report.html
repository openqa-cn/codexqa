holdStock is check-then-act; two last-unit holds can both succeed

concurrency
Evidence

readStock → available = onHand - reserved → await appendAudit → reserved += qty → putStock with no lock. Two concurrent quantity=1 holds when available=1 both pass the check. Intent: no double holding.
