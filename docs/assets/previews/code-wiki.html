系统怎么运转 一句话定位 + 主链路

inventory-service 是一个本地库存占用与退款示例：店面创建 hold，到期释放，提交后按实付金额退款。

请求从 HTTP 入口进来，应用层编排预订，领域层分别处理占用、计价、退款，存储层是 db 与可用性缓存。

主链路是 hold → expire/commit → refund。独立的 verify 脚本和需求文档用来对照缺陷，不是运行时路径。

阅读路径 按这个顺序读源码

1. p01 HTTP 入口 — 先看请求从哪进来，下单和退款是两条入口。
2. p02 预订编排 — 从 p01 列有依赖；编排 hold / commit，再决定碰库存还是计价。
3. p03 库存占用 — 从 p02 列有依赖；这里是枢纽，先搞清对外接口再往下读。改这里会同时碰到过期、提交和退款。
4. p06 存储 — 从 p03 列有依赖；缓存失效规则决定店面能不能立刻买到过期释放的库存。
